# Backtime — build rules (repo root)

Live run-of-show timing tool. **Brief, spec, and plan live in `BRIEF/`** (Drive-synced symlink,
gitignored): read `BRIEF/spec.md` for the product, `BRIEF/plan.md` for the order of work.
This file duplicates the non-negotiables because `BRIEF/` is not committed.

## The one rule that decides this build

**The arithmetic is the product, and it must be verified in the terminal before any UI exists.**
Back-time column, heavy/light delta, float solver — printed and checked against a hand calculation.
Build the UI first and you spend the back half debugging arithmetic through a rendering layer.

## Domain vocabulary — this is the credibility

- **Back-time** — work backwards from the hard end to get the wall-clock time each segment must
  start. A rundown is timed from its end, not its beginning.
- **Heavy / light** — heavy is more content than time remaining. Light lands early. One number, all show.
- **Slug** — a segment's short name; the rundown's leftmost text column, header `SLUG`. The slug
  cell is the **only** double-clickable cell — it opens a plain `<textarea>` on that session's
  scraped description.
- **Float** — a segment marked **droppable in advance**, so when you go heavy you already know what
  dies. **Float is a droppable segment, never a slack-time measurement.** In this rundown the floats
  are the turnarounds, lunch, and the buffer to happy hour — the things a producer actually compresses.

## Data — frozen, not live

- `data/rundown.json` is the **frozen fixture**, generated by `scripts/scrape_devfest.py`.
  The app reads the JSON. **The app never touches the network.**
- Re-scrape only on good wifi, well before the demo: `python3 scripts/scrape_devfest.py`
- Source publishes **start times only**. Durations are **derived** (gap to next start, capped at 50
  min; the remainder becomes an explicit float break). This is an assumption, not published data —
  keep it visible and editable in the manual table. Never present a derived duration as authoritative.
- `hard_end` is **17:00**, sourced from the happy-hour slot on the homepage, not from `/sessions`.

## Floats are live

`is_float` is not fixed by the fixture. Clicking a row's FLOAT cell toggles it, `BACK` undoes it,
and the change persists to `localStorage`. The solver only ever considers floats **strictly after**
the current index — a segment on air is not droppable.

## The readout is live, not a segment-boundary number

The on-air segment's remaining time is **clamped at zero** in `computeDelta`. Unclamped,
`plannedSec - elapsed` goes negative at exactly the rate the wall clock advances, the delta
cancels to a constant, and the readout never moves while a segment runs long. Clamped:

- On plan, the delta is perfectly **still** (asserted in the gate — a twitching readout is
  one nobody trusts; the twitch that shipped came from mixed rounding in `app.js`, where
  `nowSec()` truncated one `Date` while `segmentElapsedSec()` rounded another).
- Over plan, the overage **accumulates every second**.
- `NEXT` does **not** double-count it. The readout is continuous across the tap.

Segment starts are snapped to a whole second (`alignedNow()`) so elapsed and wall-clock cross
the second boundary together. Do not reintroduce a second independent clock reading.

## Starts are the source of truth

Durations are DERIVED from consecutive starts (`recomputeFromStarts` in `app.js`) — the same rule
the scraper used, because devfestdc.org publishes start times only. Editing a START cell therefore
changes the two adjacent durations and the back-time column follows; total planned time is
conserved. Out-of-range edits are refused with a reason, never clamped.

The table does **not** repaint while a START cell is being edited (`inlineEditOpen`). The engine
paints ~4x/second and would otherwise tear the `<input>` out mid-keystroke. Clocks keep ticking.

## Two resets, and they are not interchangeable

- **`resetRun()`** — the RESET button. Clears actuals and returns to standby, but KEEPS schedule
  edits, float marks and edited descriptions. That is prep work; a producer resetting between
  takes does not want it destroyed. Snapshotted, so BACK undoes it — hence no confirm dialog.
- **`resetAll()`** — console only (`Backtime.reset()` is an alias). Reloads the scraped fixture and
  discards everything.

Do not wire `resetAll` to a button.

## Non-negotiables

1. **Zero model calls on the critical path.** The scrape replaced paste-parse. If paste-parse comes
   back it is additive and off the critical path — it never becomes the way data gets in.
2. **Never invent a duration.** Unparseable or unknown → `planned: 0`, flagged for the user.
3. **Never name a cut that does not close the gap.** If cutting every float still leaves you heavy,
   say exactly that, with the shortfall.
4. **`BACK`/`UNDO` must work.** A mis-tapped `NEXT` will happen on stage.
5. **Clocks count past zero into negative** (over/under), colour-flipped. Never freeze at 00:00 —
   the negative number is the most useful thing on screen when you are live.
6. **Test with the network off before demoing.** Literally disconnect it.
7. **Do not build inside `BRIEF/`.** It is Google Drive-synced. Code lives in the repo root.

## Lessons

- **`float` in this project means a droppable segment, not slack time between hard hits.** The float
  solver picks which floats to drop when heavy; it never reports a gap measurement. Do not redefine
  a domain term that `BRIEF/spec.md` has already pinned down — read the spec before proposing
  vocabulary.
- **Check `BRIEF/` for an existing spec/plan before planning anything in this repo.** The brief is a
  gitignored symlink, so it is invisible to `git`-based orientation but present on disk.
